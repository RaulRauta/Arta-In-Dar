# SEC-005 — CSP compatibilă, dar nu strictă

- Severitate: Informational
- Status: Hardening recomandat
- CWE: CWE-693
- Componentă afectată: headere globale și Studio
- Fișier și linii: `next.config.ts:37-51`, `next.config.ts:84-99`

## Descriere

CSP este prezentă și mult mai bună decât lipsa unei politici, dar folosește `script-src 'unsafe-inline'` pe site și `unsafe-inline`/`unsafe-eval` pe Studio pentru compatibilitate. Acest lucru reduce protecția CSP împotriva unor clase de XSS.

## Condiții necesare exploatării

Este necesară o vulnerabilitate XSS separată sau conținut malițios care ajunge în DOM.

## Source-to-sink

Header CSP generat în `next.config.ts` → browser.

## Impact realist

În cazul unui XSS, CSP ar limita mai puțin execuția decât o politică bazată pe nonce/hash.

## Dovadă

Headerul de producție conține `script-src 'self' 'unsafe-inline'`; Studio are `unsafe-eval`.

## Reproducere sigură

Verificare headere:

```bash
curl -I https://arta-in-dar.vercel.app/
```

## Remediere concretă

Introdu nonce/hash pentru scripturi inline unde este fezabil. Păstrează politică separată pentru `/studio`, deoarece Sanity poate necesita reguli mai permisive.

## Teste de adăugat

- Smoke tests vizuale pe toate paginile.
- Verificare CSP report-only înainte de enforce.

## Verificare după remediere

Confirmă că site-ul și Studio funcționează fără erori CSP în consolă.

## Incertitudini

Next/Sanity pot necesita concesii de compatibilitate; recomand întărire incrementală, nu schimbare bruscă.
